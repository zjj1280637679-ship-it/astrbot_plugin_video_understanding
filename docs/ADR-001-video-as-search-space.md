# ADR-001：将视频建模为可查询的信息空间

状态：Accepted

日期：2026-08-13

## 背景

本插件的目标不是对视频做一次性摘要，也不是为 AstrBot 重新实现视频理解基础设施。AstrBot 已经负责接收 `Video` 消息组件、管理模型卡、Provider、工具循环和会话；部分已有模型卡已经具备视频输入能力。

真正缺失的是一种“主模型不能直接读取视频时，仍可在推理过程中反复查询视频”的薄层能力。

## 决策

将视频视为一个**有界、多模态、可反复自然语言查询的信息空间**。

- 视频：被搜索的信息空间。
- 视频能力模型卡：执行语义搜索的引擎。
- 主模型：制定查询、根据结果继续追问、综合证据并最终回答。
- AstrBot Tool Loop：负责工具调用循环。
- 本插件：仅负责绑定当前视频、暴露 `query_video`、把查询交给已选视频模型卡、返回观察结果。

因此正确流程是：

```text
用户问题 + 视频
      ↓
主模型
      ↓
query_video(子问题 1)
      ↓
视频模型卡读取视频
      ↓
结果 1 返回主模型
      ↓
主模型更新判断
      ↓
query_video(子问题 2)
      ↓
……
      ↓
证据充分
      ↓
主模型最终回答
```

## 明确不采用的方案

### 一次性视频转述

不采用：

```text
用户问题 → 视频模型一次性回答 → 主模型
```

原因：该结构把查询规划提前固化成一次调用，失去类似网络搜索的“查到一点、发现缺口、继续查”的能力。

### 插件自建 Agent 循环

不采用。AstrBot 已经拥有 Tool Loop，本插件不再实现独立编排器。

### 插件自建视频基础设施

不采用。插件不负责：

- 平台视频下载；
- Base64/URL/本地路径适配；
- 供应商上传协议；
- 模型能力发现；
- FFmpeg 抽帧；
- OCR/STT 降级；
- 独立视频数据库；
- 独立长期会话。

这些均属于 AstrBot 核心、Provider 或其他专门插件的职责。

## 激活策略

第一版支持两种策略：

- `fallback_only`：当前主模型不具备视频输入能力时，才暴露 `query_video`。
- `always_when_video`：只要本轮存在视频，就暴露 `query_video`，允许专用视频模型承担搜索职责。

## 成功标准

1. 没有视频时插件不改变主模型请求。
2. 有视频时只提供查询工具，不提前生成摘要。
3. 主模型可以连续调用 `query_video` 多次。
4. 每次调用只返回当前查询相关的视频观察材料。
5. 最终回答始终由主模型生成。
6. 插件代码不包含供应商专属 SDK 或视频处理流水线。
